# 산출물 골격: §1~§10 시스템 프롬프트 템플릿

이 스킬이 만드는 최종 산출물(`{파일명}-prompt.md`)은 아래 §1~§10 구조를 그대로 따른다. 각 섹션은 **분석한 덱에서 실제로 관찰한 값**으로 채운다. 관찰되지 않은 항목은 지어내지 말고 "정보 부족: {이유}"로 남긴다.

핵심 원칙 세 가지.

1. **이 템플릿은 뼈대이지 정답이 아니다.** 아래 예시 값(색 이름, 레이아웃 이름)은 한 IR 덱에서 나온 것이다. 분석 대상 덱이 카드 3종·타임라인·풀블리드 사진만 쓴다면, 그 세 가지만 카탈로그에 넣는다. 억지로 10개 레이아웃이나 특정 팔레트를 채우지 않는다.
2. **생성될 프롬프트는 "다음 사람이 이 덱과 똑같은 새 슬라이드를 만들도록" 지시하는 문서다.** 그래서 값이 구체적이고 복제 가능해야 한다. "세련된 색"이 아니라 `#0B5A3C`, "적당한 여백"이 아니라 `padding: 6cqi 7cqi 8cqi`.
3. **한국어로 쓴다.** 단, 코드·토큰·폰트명·HTML 예시는 원문 그대로 둔다.

---

## §1. 역할과 기본 규격

이 프롬프트를 받는 모델이 무엇을 하는 사람인지, 무엇을 기본값으로 출력하는지 정의한다.

담을 것:
- 역할 한 줄 (예: "너는 {브랜드/덱 성격} 슬라이드를 만드는 디자이너다")
- 기본 출력 형식 (HTML 단일 파일 / PPTX). 사용자가 명시하지 않으면 무엇을 만들지 명시
- 슬라이드 비율(16:9 등)과 1덱 기본 분량

예시:
```
너는 라이너 IR 덱과 동일한 시각 언어로 새 슬라이드를 만드는 디자이너다.
사용자가 형식을 지정하지 않으면 16:9 단일 HTML 덱을 만든다.
```

## §2. 디자인 시스템

덱의 시각 언어를 토큰으로 고정한다. 상세 추출 기준은 `analysis-framework.md`.

담을 것:
- **색상 토큰**: 관찰된 모든 색을 `--이름: #HEX; /* 용도 */` 형식으로. 중요도 순. 개수는 덱에 있는 만큼(3개면 3개)
- **타이포그래피**: 폰트 스택, 요소별(H1/H2/본문/라벨/숫자) weight·size 범위·letter-spacing·line-height 표
- **그리드·여백**: 비율, 패딩(단위 명시: px/cqi/em), 그리드 스케일(8의 배수 등)
- **데코레이션**: 표지 배경, 로고 위치, 섹션 라벨, 카드·테이블 스타일, 특수 장식(코너 괄호·구분선·질감)

## §3. 슬라이드 레이아웃 카탈로그

**덱에 실제로 등장한 레이아웃만** 유형별로 정리한다. 각 유형에 이름·용도·구조(어떤 요소가 어디에)를 붙인다. 개수는 고정이 아니다.

각 레이아웃 항목 형식:
```
### 레이아웃 N: {이름}
- 용도: {언제 쓰는가}
- 구조: {상단 무엇, 본문 무엇, 하단 무엇}
- 예시 HTML 골격 (선택)
```

흔히 나오는 유형(참고용, 이것으로 강제하지 말 것): 표지, 목차/아젠다, 섹션 전환, 본문+카드, 비교 테이블, 데이터 차트, 다이어그램, 인용/스테이트먼트, 마무리+다음 단계.

## §4. 콘텐츠 작성 규칙

카피를 어떻게 쓰는지 규정한다. 상세는 `content-rules.md`.

담을 것: 제목·부제의 길이/톤/종결 표현, 강조 방식(굵음 vs 배경색 규칙), 카드 제목·본문 길이, 테이블·다이어그램 텍스트 규칙.

## §5. 한국어 표기 원칙

이 덱이 지키는 한국어 규칙을 명문화한다(`content-rules.md` 4.7 참조).

담을 것: em dash 사용 여부, 번역투 처리, 주술 구조 정합, 명사구 깊이 한도, 종결 표현 일관성 규칙. 덱이 한국어가 아니면 이 섹션은 해당 언어의 표기 관습으로 대체하고 그 사실을 명시.

## §6. 숫자·단위·약어

정량 표기 규칙(`content-rules.md` 4.8 참조).

담을 것: 천 단위 콤마, 소수점 자릿수, 단위 위치(%, x, bp, 통화), 방향 부호(+/-), 시점 표기(분기·월·일 형식), 영문 약어 표기, 고유명사·브랜드 표기 규칙.

## §7. 데이터 시각화

차트·테이블·다이어그램의 시각 규격.

담을 것: 차트 유형별 색 배정(자사 vs 비교군), 축·범례 규격, 테이블 헤더/강조 셀 규칙, 다이어그램 계층 색·화살표 스타일. 관찰된 것만.

## §8. 접근성과 가독성

읽히는 슬라이드가 되기 위한 규칙.

담을 것: 배경-텍스트 대비(어두운 배경엔 흰 텍스트 등), 최소 폰트 크기, 한 슬라이드 정보 밀도 상한, 색만으로 정보를 구분하지 않기(라벨 병기). 덱에서 관찰된 실제 관행을 기록하고, 명백히 부족하면 개선 규칙으로 보강.

## §9. 산출·기술 규격

실제 파일을 만들 때의 기술 규칙.

담을 것(HTML 산출 기준): 폰트 로딩 방식, 컨테이너 쿼리/반응형 단위, 전체화면·네비게이션(클릭/화살표/스크롤), 인쇄·PDF(`@media print`, `page-break`), 파일 자기완결성(외부 의존 최소화). PPTX 산출이면 마스터 슬라이드·플레이스홀더 규칙으로 대체.

## §10. 품질 체크리스트

생성된 슬라이드를 넘기기 전에 스스로 점검하는 목록. 이 덱의 정체성을 지켰는지 확인하는 5~10개 항목으로.

예시:
```
- [ ] 색은 §2 토큰만 사용했는가
- [ ] 제목 종결 표현이 §5 규칙과 일치하는가
- [ ] 숫자·단위가 §6 규칙과 일치하는가
- [ ] em dash 0개인가
- [ ] 레이아웃이 §3 카탈로그 안에 있는가
- [ ] 어두운 배경 위 텍스트 대비가 충분한가
```

---

## 완결성 규칙

- §1~§10을 모두 포함한다. 관찰 못 한 섹션은 비우지 말고 "정보 부족: {무엇을 못 봤는지}"로 남겨 다음 사람이 채우게 한다.
- 각 섹션에 최소 하나의 구체 값 또는 예시를 넣는다. 추상적 설명만 있는 섹션은 복제 불가능하므로 실패로 본다.
- 최종 분량 대략 10~20KB(짧은 덱은 더 짧아도 된다. 분량 자체가 목표는 아니다).
