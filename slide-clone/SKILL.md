## 개요

기존 슬라이드 덱을 분석해 **그 덱과 똑같은 슬라이드를 다시 만들 수 있는 시스템 프롬프트**로 바꾼다.

왜 이게 유용한가. 잘 만든 덱 한 벌에는 재사용 가능한 규칙(색·타이포·레이아웃·카피 톤·숫자 표기)이 통째로 들어 있다. 그 규칙을 한 번 문서로 뽑아 두면, 다음부터는 "이 시스템으로 새 슬라이드 만들어줘" 한 줄로 같은 품질을 반복 생산할 수 있다. 단발 산출물이 아니라 재사용 자산을 남기는 일이다.

산출물은 §1~§10 구조의 한국어 시스템 프롬프트다. 정확한 골격과 각 섹션에 무엇을 채우는지는 `references/prompt-template.md`에 있다. 작업 시작 전 그 파일을 먼저 읽는다.

## 입력 / 출력

| 항목 | 형식 |
|---|---|
| 입력 | PDF, 또는 PowerPoint(.pptx/.ppt) |
| 출력 | 마크다운 시스템 프롬프트 (§1~§10) |
| 언어 | 한국어 (코드·토큰·폰트명·HTML 예시는 원문) |
| 저장 | `~/Desktop/{원본파일명}-prompt.md` |
| 크기 | 대략 10~20KB (덱이 단순하면 더 짧아도 됨) |

## 워크플로우

### Step 1. 덱을 읽는다

- 전체를 훑어 어떤 슬라이드 유형이 있는지 파악하고, 대표 페이지 10~15장을 집중 분석한다. 페이지가 많아도 유형은 대개 5~10가지로 수렴한다.
- **PDF**: 네이티브로 읽어 텍스트·구조를 보고, 색·여백은 페이지를 이미지로 렌더해 확인한다(방법은 아래 Step 2).
- **PPTX**: `.pptx`는 zip이다. 풀어서 `ppt/theme/theme1.xml`(색·폰트 테마), `ppt/slideMasters`, `ppt/slides/*.xml`을 직접 읽으면 PDF보다 정확한 값을 얻는다. pptx가 있으면 이 경로를 우선한다.

### Step 2. 디자인 시스템을 추출한다

"추측하지 말고 정확히"가 이 스킬의 생명이다. 그러려면 방법이 있어야 한다. **정확한 색·폰트·여백 추출 방법은 `references/analysis-framework.md`의 §2.0을 따른다** (페이지 렌더 → 픽셀 샘플링, `pdffonts`로 폰트 조회 등).

뽑을 것: 색상 토큰(전부, hex로), 타이포그래피(요소별 weight·size·spacing·line-height), 그리드·여백(단위 명시), 데코레이션(표지·섹션 라벨·카드·테이블·특수 장식). 끝내 확정 못 한 값은 지어내지 말고 `(근사)` 표시나 "정보 부족"으로 남긴다.

### Step 3. 실제 등장한 레이아웃을 카탈로그로 만든다

**덱에 실제로 있는 레이아웃만** 유형별로 정리한다. 개수는 고정이 아니다. 3종만 쓰는 덱이면 3종만, 다양하면 그만큼. 각 유형에 이름·용도·구조를 붙인다.

흔히 보이는 유형(참고용이지 채워야 할 목록이 아니다): 표지, 목차/아젠다, 섹션 전환, 본문+카드, 비교 테이블, 데이터 차트, 다이어그램, 인용/스테이트먼트, 마무리. 분석 대상 덱이 이 중 일부만 쓰거나, 여기 없는 독자 레이아웃을 쓰면 **본 대로** 기록한다. 억지로 9개를 채우지 않는다.

### Step 4. 콘텐츠·한국어·숫자 규칙을 분석한다

카피가 어떻게 쓰였는지 규칙으로 뽑는다. 제목·부제 톤과 종결 표현, 강조 방식, 카드·테이블 텍스트 규칙, 한국어 표기 원칙(em dash·번역투·주술·종결 일관성), 숫자·단위·약어 표기. **상세 기준은 `references/content-rules.md`.**

### Step 5. §1~§10을 조립하고 저장한다

`references/prompt-template.md`의 골격에 Step 2~4에서 관찰한 값을 채워 완전한 시스템 프롬프트를 만든다. §1~§10을 모두 포함하고, 각 섹션에 복제 가능한 구체 값을 최소 하나 넣는다. 관찰 못 한 섹션은 "정보 부족: {이유}"로 남긴다.

저장: `~/Desktop/{원본파일명}-prompt.md`. 그다음 사용자에게 짧게 보고한다(색 개수, 레이아웃 종류, 핵심 콘텐츠 규칙, 파일 경로). 보고 형식 예시는 `references/examples.md`.

## 산출물 골격 (§1~§10 한눈에)

| § | 섹션 | 핵심 |
|---|---|---|
| 1 | 역할과 기본 규격 | 역할 한 줄, 기본 출력 형식(HTML/PPTX), 비율 |
| 2 | 디자인 시스템 | 색 토큰, 타이포, 그리드, 데코 |
| 3 | 레이아웃 카탈로그 | 실제 등장한 레이아웃만 |
| 4 | 콘텐츠 작성 규칙 | 제목·강조·카드·테이블 카피 |
| 5 | 한국어 표기 원칙 | em dash·번역투·주술·종결 |
| 6 | 숫자·단위·약어 | 콤마·소수·단위 위치·시점 표기 |
| 7 | 데이터 시각화 | 차트·테이블·다이어그램 규격 |
| 8 | 접근성과 가독성 | 대비·최소 크기·정보 밀도 |
| 9 | 산출·기술 규격 | 폰트 로딩·네비·인쇄·자기완결성 |
| 10 | 품질 체크리스트 | 넘기기 전 자기 점검 목록 |

각 섹션에 무엇을 채우는지 상세는 `references/prompt-template.md`.

## 품질 기준 (이걸 넘겨야 완성)

1. **완결성**: §1~§10 모두 포함. 빈 섹션은 "정보 부족: {이유}"로 명시(빈칸 방치 금지).
2. **복제 가능성**: 각 섹션에 구체 값이 있다. "세련된 색"이 아니라 `#0B5A3C`. 추상 설명만 있는 섹션은 실패.
3. **정확성**: 색·폰트·여백은 Step 2 방법으로 확인한 값. 확정 못 하면 `(근사)` 표시. 정밀값을 지어내지 않는다.
4. **과적합 금지**: 레이아웃·색 개수를 특정 숫자로 강제하지 않는다. 이 덱에 있는 만큼만.
5. **한국어**: 모든 섹션 한국어(코드·토큰·폰트명·HTML 예시 제외).
6. **기본 출력 형식 명시**: §1에서 사용자 미지정 시 무엇을 만들지(HTML 또는 PPTX) 못 박는다.
